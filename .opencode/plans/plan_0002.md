> Status: in progress · Scope: all content chapters, piloted on Biology ch. 8 · Owner: agent + user review
> Date: 27 Oct 2026

---

## 0. Decision in one paragraph

Reading quality is a **shape** problem, not a writing problem: the facts are already right, the presentation is not. So the fix is made *testable* rather than remembered — a one-page playbook the agent reads before every chapter, and a static linter that catches the exact failure modes. Both are committed. From here, every chapter is polished as a sequence of **approved shape maps**, not free-form rewriting: *source paragraph → vehicle*, approved in 30 seconds, then written once.

## 2. The linter — rules and thresholds

| Rule | Check | Severity |
|---|---|---|
| P1 | `<p>` holding 3+ sentences | error |
| P2 | `<p>` over 60 words | warning |
| P3 | `<p>` with 3+ commas and an "and" (inline list) | warning |
| P4 | `etc.` anywhere in copy | warning |
| P5 | Model text cites `Fig. x.y` that the page never references | error |
| P6 | Table cell over 25 words | warning |
| P7 | Heading level jump (`h2 → h4`) | warning |

```bash
node scripts/audit-presentation.cjs --chapter <slug>   # one chapter (the normal case)
node scripts/audit-presentation.cjs                    # whole corpus (776 errors today — the backlog)
```

P5 resolves the model text automatically: `Developer_Deliveries/Chapters/{Subject}/{slug}-extracted.md`, falling back to `-clean.md`, then `-raw.md`.

## 3. Workflow for every chapter

1. **Audit** — `--chapter <slug>`; the output is the worklist.
2. **Read the model text** — every heading, figure, table, activity.
3. **Shape map** — a table of *source paragraph → vehicle*, posted for approval before any JSX.
4. **Write** — apply the ten laws; reuse components before inventing any.
5. **Post-flight** — linter, `verify-latex`, `typecheck`, 360 px, dark mode, gallery if a component is new.
6. **Push** — once, at the milestone.
