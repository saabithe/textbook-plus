# Plan 0001 — A chemical-structure engine for Chemistry chapters

> Status: proposed · Scope: Chemistry (then reusable by Biology) · Owner: agent + user review
> Date: 26 Oct 2026

---

## 0. Decision in one paragraph

Draw structures **once, at authoring time**, with **RDKit** (a real cheminformatics toolkit, not an AI guess), from a **SMILES string that is committed to git as the source of truth**. The renderer emits a small, self-contained SVG that is committed too. The app ships **no chemistry engine** — it just inlines the SVG. Every structure must pass **seven automated gates** plus **one human eyeball check** before it can ship. AI never draws a bond by hand; AI only supplies SMILES, which the toolkit then validates chemically.

---

## 1. Why the obvious approaches fail

| Approach | Why it fails |
| --- | --- |
| AI hand-writes SVG paths / "describes" the structure | No valence checking. A plausible-looking but chemically wrong drawing ships silently — exactly the failure the user is afraid of. |
| AI hand-writes SMILES and trusts it | SMILES is where the real errors live (wrong ring size, missing methyl, lost stereochemistry). Needs automated chemistry checks, not trust. |
| Fetch PNG from PubChem at build/runtime | Network dependency, no offline/PWA support, wrong depiction style, licensing ambiguity, and the same compound can be drawn differently from NCERT. |
| Runtime JS chemistry engine in the browser | `@rdkit/rdkit` WASM is ~7.5 MB, `indigo-ketcher` is ~45 MB. Unacceptable for a reading app, and adds a runtime failure mode. |

The fix is the opposite of automation-at-render-time: **a deterministic build step with a chemistry compiler, and a review artifact a human can check in seconds.**

## 2. Proof of capability — verified today on this machine

A throwaway venv in `%TEMP%` proved the whole chain before writing this plan.

| Item | Verified result |
| --- | --- |
| Toolchain installs | `python -m venv` + `pip install rdkit` → **RDKit 2026.09.1** on Python **3.13.7**, Windows, no compiler needed |
| Single molecules | Ethanol, benzene, aspirin, caffeine, glucose, lactic acid, nitrobenzene, cholesterol, adenosine all render |
| Stereochemistry | `C[C@@H](O)C(=O)O`, `C/C=C\C` render with wedge/dash + E/Z annotation |
| Charges / ions | `[O-]S(=O)(=O)[O-]`, `[Cu+2]` render with correct charges |
| Coordination compounds | `[NH3]->[Cu+2](<-[NH3])(<-[NH3])<-[NH3]` → **4 dative bonds parsed**, formula `H12CuN4+2` |
| Reactions | `CC(=O)O.OCC>[H+]>CC(=O)OCC` renders with the reagent **above the arrow** |
| Polymers | Repeat unit with `*` attachment points parses (2 dummies) |
| Formula / mass | `CalcMolFormula` + `MolWt` give exact `C9H8O4` / `180.16` |
| Identity round-trip | SMILES → InChI → SMILES returns an **identical** canonical molecule |
| **Bad input is rejected** | Pentavalent carbon, non-kekulizable 5-ring, over-valent oxygen, unknown element → **hard parse errors**, nothing drawn |
| Output size | 1.9 KB (ethanol) → 10 KB (caffeine) → 20.8 KB (adenosine) |
| Output structure | Each bond carries `class='bond-0 atom-0 atom-1'`; `<rdkit:mol>` metadata can embed per-atom SMILES |
| Colours | Bonds `#000000`, N `#0000FF`, O `#FF0000` — themeable by one string replacement |
| Human review artifact | 9 structures → one 54 KB PNG contact sheet |

**Conclusion: the capability is real, cheap, offline-safe and fully auditable. No new runtime dependency.**

## 3. Architecture

```
structures.json          (authored: SMILES + caption + NCERT formula + source ref)
        │
        │  python scripts/chem/build_structures.py
        │  ├─ parse + sanitize  → hard fail on any chemistry error
        │  ├─ formula/mass compare against authored values
        │  ├─ InChI round-trip → stereochemistry preserved
        │  ├─ render SVG (transparent bg, themed strokes, metadata)
        │  └─ write structures.generated.ts
        ▼
structures.generated.ts  (committed: svg string + formula + mw + inchiKey + atom count)
        │
        │  node scripts/check-structures.cjs   ← runs inside `npm run build`
        ▼
<MoleculeStructure />    inline SVG in the page (no network, no engine, prints crisply)
```

### Rejected alternatives (recorded so nobody re-litigates them)

- **Runtime RDKit WASM** — 7.5 MB, slow first paint, needs a fallback path anyway. Keep as a *future* option only if we ever want an interactive "edit the molecule" tool.
- **smiles-drawer (MIT, pure JS, 2.4.1)** — decent depictions, but it is a *drawer*, not a validator: it will happily lay out a chemically impossible molecule. Accept only as an emergency fallback for a chapter where Python is unavailable.
- **Indigo / Ketcher** — excellent (Apache-2.0), and the one thing RDKit lacks is a first-class *reaction-scheme* and *aromatic-circle* style. Use it only if the pilot proves a specific NCERT convention can't be matched — not as the default.

## 4. Data model and file layout

```
textbook-plus/src/content/chemistry/{chapter-slug}/
├── structures.json             ← authored, small, git-diffable
├── structures.generated.ts     ← machine output, "DO NOT EDIT"
├── page.tsx                    ← imports the generated map
└── …

textbook-plus/src/components/content/chemistry/
├── MoleculeStructure.tsx
└── ReactionScheme.tsx          (phase 3)
```

### `structures.json` — the source of truth

```json
{
  "aspirin": {
    "smiles": "CC(=O)Oc1ccccc1C(=O)O",
    "name": "Aspirin",
    "ncertName": "acetylsalicylic acid",
    "caption": "Aspirin — the acetyl group on the –OH of salicylic acid removes its acidity.",
    "formula": "C9H8O4",
    "mw": 180.16,
    "source": "§8.6, Example 8.11, p.241",
    "size": [420, 300]
  }
}
```

Rules:
- `smiles` is the **only** chemical truth. Everything else is checked against it.
- `caption` explains; it never restates a bond count.
- `source` must point at a real section/page in the extraction file.

### `structures.generated.ts`

```ts
// AUTO-GENERATED by scripts/chem/build_structures.py — DO NOT EDIT
export const STRUCTURES = {
  aspirin: {
    svg: "<svg … data-smiles='…' data-inchikey='…' data-formula='C9H8O4' …>",
    formula: "C9H8O4", mw: 180.16, inchiKey: "BSYNRYMUTXBXSQ-UHFFFAOYSA-N",
    atoms: 13, generator: "rdkit 2026.09.1", hash: "sha256:…"
  },
} as const;
```

Every SVG carries `data-smiles`, `data-inchikey`, `data-formula` on its root element, so a future reader (or a script) can identify the exact molecule without any chemistry library.

### Component API

```tsx
<MoleculeStructure {...STRUCTURES.aspirin} caption="Aspirin" />
```

Props: `svg`, `caption?`, `formula?` (renders a small muted line), `highlight?` (atom indices → CSS class hook), `maxWidth?`, `float?` (wrap text around small structures), `showSmiles?` (advanced disclosure).

Behaviour:
- `dangerouslySetInnerHTML` of our own generated markup (no external input).
- Root `<figure role="img" aria-label={caption}>` — no caption-less figures.
- Dark mode: generator rewrites `stroke:#000000` → `stroke:currentColor`; heteroatom colours are kept (they read fine on both themes).
- Never scales below the generated font size: `width:100%; height:auto; max-width:{px}`.
- Prints well by default; add `print-color-adjust: exact` on the figure.
- No `next/image` (SVG is inlined, so it inherits CSS and needs no request).

## 5. The seven gates — how "no mistakes" is enforced

Every structure must pass all seven. Gates 1–5 run in the generator; 6 is human; 7 runs in `npm run build`.

| # | Gate | Catches | Mechanism |
| --- | --- | --- | --- |
| **G1** | **Existence in source** | AI inventing a compound the chapter never had | `ncertName` must appear verbatim in `{slug}-extracted.md`, and `source` must cite a real section/page. Hard fail otherwise. |
| **G2** | **Parse + sanitize** | Wrong valence, impossible ring, unknown element, unclosed ring | RDKit `MolFromSmiles` + `SanitizeMol`. Verified today: all 4 malformed test inputs are rejected. |
| **G3** | **Formula match** | Wrong number of atoms — the #1 silent error | Computed `CalcMolFormula` must equal the authored `formula` (taken from NCERT). |
| **G4** | **Mass match** | Correct formula, wrong molecule is still possible | Computed `MolWt` must be within 0.01 of authored `mw` when NCERT gives one. |
| **G5** | **Stereochemistry preserved** | Losing `@@`, `/`, `\` — chiral centres silently flattened | SMILES → InChI → SMILES must be identical; if the authored SMILES has stereo, the InChI must contain a stereo layer. |
| **G6** | **Human eyeball** | Everything chemistry can't see: wrong *isomer chosen*, wrong group highlighted, unreadable layout | One **contact-sheet PNG per chapter** (all structures, labelled) written to `Developer_Deliveries/`, reviewed by the user before merge. 9 structures = ~5 seconds to scan. |
| **G7** | **Structural lint + build** | Missing/unreferenced entries, leftover black strokes, dead figures, budget blowout | `node scripts/check-structures.cjs`: every `<MoleculeStructure>` id exists; every entry is used; no `stroke:#000000`; no `<script`/external href; size budget (warn 25 KB, fail 40 KB); generator hash matches. |

**Non-negotiable rule:** a structure that fails any gate is **deleted, not patched**. A missing figure is a known gap; a wrong figure is a defect.

## 6. Scope matrix — what gets automated and what never does

| Content | Verdict | How |
| --- | --- | --- |
| Organic molecules, functional groups, isomers | **Automate** | RDKit from SMILES |
| Stereochemistry, E/Z, optical isomers | **Automate** | Isomeric SMILES + stereo annotation |
| Ions, salts, charged species | **Automate** | `[O-]`, `[Cu+2]`; counter-ions in one canvas |
| Coordination compounds / complexes | **Automate, review colour** | Dative bonds work; NCERT often draws plain lines to the metal, so the pilot must confirm visual convention |
| Single-step reactions with reagents above the arrow | **Automate** | Reaction SMILES `A.B>agent>C` |
| Multi-step schemes / industrial flows | **Assist** | Compose per-step SVGs with our own arrow/box layout; never one giant auto-layout |
| Polymers (repeat units) | **Assist** | `*`-dummy repeat unit; brackets/typeset when NCERT writes `[CH₂–CHCl]ₙ` |
| Biomolecules (glucose ring, amino acid, nucleotide) | **Automate** | Verified: adenosine 19 atoms, 20 KB |
| **Curly-arrow mechanisms** | **Manual SVG** | No reliable automated renderer exists. Compose an overlay on the RDKit base drawing only when needed; keep it hand-made and reviewed |
| Crystal lattices, unit cells (NaCl fcc), band diagrams | **Manual SVG** | Not molecular |
| Orbital / crystal-field splitting, energy profiles | **Manual SVG** | Already the physics-component pattern |
| Chair/Newman conformations | **Manual SVG** | RDKit 2D cannot express them |

Being explicit about the "never" rows is what makes the "always" rows trustworthy.

## 7. Error catalogue → which gate stops it

| Realistic AI error | Gate that stops it |
| --- | --- |
| Draws a compound the chapter never mentions | G1 |
| Wrong ring size (`c1cccc1`) | G2 (verified: hard fail) |
| Missing/extra methyl → wrong formula | G3 |
| Correct skeleton, wrong isomer | G6 (human: contact sheet) |
| Chiral centre flattened to a plain bond | G5 |
| Written as neutral when NCERT shows an ion | G3 (formula includes charge) |
| Reaction shown without its reagent/condition | G7 (manifest requires `agents` for reactions) + G6 |
| Structure ships but is never used, or used but never generated | G7 |
| Dark-mode invisible bonds | G7 (no `#000000` allowed) |

## 8. Phases and acceptance criteria

### Phase 0 — Tooling (no content change)
- `scripts/chem/requirements.txt` (`rdkit==2026.09.1`), `scripts/chem/README.md`, venv instructions; venv path gitignored.
- `scripts/chem/build_structures.py` (generator + G1–G5), `scripts/chem/contact_sheet.py` (G6 artifact), `scripts/check-structures.cjs` (G7).
- `MoleculeStructure.tsx` + `/dev/design` gallery entry.
- npm scripts: `chem:build`, `chem:sheet`, `chem:check`; `chem:check` wired into `build`.
- **Done when:** gallery renders a 4-structure demo, `npm run build` passes, and a deliberately corrupted `structures.json` fails the build with a readable message.

### Phase 1 — Pilot on **Chapter 8 (Aldehydes, Ketones and Carboxylic Acids)**
- Inventory every structure NCERT depicts in that chapter, from the extraction file.
- Author `structures.json`, generate, review the contact sheet with the user, fix, commit.
- **Done when:** 100 % of NCERT structures in ch.8 exist, 7/7 gates pass, user signs off on the contact sheet, chapter reads correctly in light + dark mode + print.

### Phase 2 — All ten Chemistry chapters (parallel, per the Parallel Batch Rule)
- One subagent per chapter produces `structures.json` + generated module + page wiring; **I** run the gates, build, and the contact-sheet review batch.
- Deliverable per chapter: a gap report (structures NCERT shows vs structures now in the page).
- **Done when:** 10/10 chapters pass G1–G7, each chapter's contact sheet approved, `npm run build` green.

#### Phase 2 — result (rollout complete, awaiting G6 sign-off)

The pilot ran on **haloalkanes-and-haloarenes**, not ch.8 as first planned: it is the chapter with the
most structures whose *shape* matters, so it stress-tests the pipeline hardest. Ch.8 became an ordinary
rollout chapter and produced two figures.

| Chapter | Figures | Outcome |
| --- | --- | --- |
| haloalkanes-and-haloarenes (pilot) | 12 | polyhalogen compounds, freons, DDT, chlorobenzene/biphenyl, dibromopropane, (R)/(S)-butan-2-ol |
| biomolecules | 9 | α/β-glucopyranose, α/β-fructofuranose, sucrose, maltose, glycyl-L-alanine, β-D-ribofuranose, β-D-deoxyribofuranose |
| alcohols-phenols-and-ethers | 4 | glycerol, phenol, salicylic acid, anisole |
| amines | 4 | aniline, benzylamine, 2,4,6-tribromoaniline, p-hydroxyazobenzene |
| aldehydes-ketones-and-carboxylic-acids | 2 | hexan-3-one ethylene ketal, cyclobutanone semicarbazone |
| solutions | 2 | phenol + aniline (the negative-deviation H-bond pair) |
| coordination-compounds | 1 | EDTA⁴⁻ (hexadentate: the one shape fact a formula cannot carry) |
| chemical-kinetics | 0 | every figure is a plot or an energy profile |
| electrochemistry | 0 | cells, electrodes, conductivity apparatus — schematics |
| d-and-f-block-elements | 0 | ionic formulas, lattices, orbital/CFSE diagrams |

**34 figures across 7 chapters; three chapters legitimately zero.** Out of 116 inventoried structures,
82 were deliberately left as condensed formulas the page already typesets.

What the rollout proved cannot be generated from SMILES, and therefore stays hand-authored:
octahedral/tetrahedral/cis–trans geometry (a flat depiction is indistinguishable or actively wrong),
chelate rings, H-bonded dimers and other non-covalent assemblies, Fischer projections, curly-arrow
mechanisms, crystal lattices, and orbital/CFSE diagrams.

Two generator defects were found by the rollout and fixed before commit: `caption`/`source` were never
emitted into `structures.generated.ts` (so no figure displayed its caption), and the `data-smiles`
provenance stamp was not XML-escaped (so any dative-bond SMILES broke the document).

### Phase 3 — Reactions and multi-step schemes
- `ReactionScheme.tsx`: `[reactant] --condition--> [product]`, stacked/composed schemes, arrow labels from the manifest.
- Extend `TableCard`/`Comparison` cells to accept a structure (so "compare A and B" can show molecules).

### Phase 4 — Mechanism layer (deliberately narrow)
- A hand-authored overlay convention on top of an auto-rendered base (curly arrows, electron pairs), with highlight classes already provided by RDKit (`bond-0 atom-2`).
- No automation of arrow placement. Ever.

### Phase 5 — Reuse
- Biology (amino acids, nucleotides, steroid hormones) and any future organic content share the same component and gates.

## 10. Risks and fallbacks

| Risk | Mitigation |
| --- | --- |
| Python/RDKit unavailable on a future machine | Generated files are committed; only regeneration needs Python. Node linter keeps the build honest. |
| NCERT depiction differs from RDKit's tidy layout (aromatic circles, dative lines, condensed formulas) | Pilot decides per convention; where a match is impossible, use the `Formula` typeset or a hand SVG — never a wrong molecule. |
| A structure is chemically right but pedagogically wrong (wrong isomer highlighted) | Only G6 catches it — so the contact sheet is mandatory, not optional. |
| Layout looks cramped for large molecules | Generator budget (warn 25 KB / fail 40 KB) + per-entry `size` override. |
| Content drift: page edited, structures stale | G7 fails the build on unused/orphaned entries. |
