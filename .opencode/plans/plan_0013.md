#### Step 2: Database Schema (SQL Migrations)
Create `supabase/migrations/` directory with:

```sql
-- 001_create_tables.sql

-- User progress tracking
CREATE TABLE user_progress (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  subject_slug TEXT NOT NULL,
  chapter_slug TEXT NOT NULL,
  completed BOOLEAN DEFAULT FALSE,
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, subject_slug, chapter_slug)
);

-- Practice data
CREATE TABLE user_practice (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  subject_slug TEXT NOT NULL,
  chapter_slug TEXT NOT NULL,
  questions_revealed TEXT[] DEFAULT '{}',
  flashcards_known TEXT[] DEFAULT '{}',
  flashcards_unknown TEXT[] DEFAULT '{}',
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, chapter_slug)
);

-- User profiles (for admin role)
CREATE TABLE user_profiles (
  id UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY,
  display_name TEXT,
  role TEXT DEFAULT 'user' CHECK (role IN ('user', 'admin')),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- RLS policies
ALTER TABLE user_progress ENABLE ROW LEVEL SECURITY;
ALTER TABLE user_practice ENABLE ROW LEVEL SECURITY;
ALTER TABLE user_profiles ENABLE ROW LEVEL SECURITY;

-- Users can only read/write their own data
CREATE POLICY "Users manage own progress" ON user_progress
  FOR ALL USING (auth.uid() = user_id);

CREATE POLICY "Users manage own practice" ON user_practice
  FOR ALL USING (auth.uid() = user_id);

CREATE POLICY "Users manage own profile" ON user_profiles
  FOR ALL USING (auth.uid() = id);

-- Admin can read all (for admin panel)
CREATE POLICY "Admins read all progress" ON user_progress
  FOR SELECT USING (
    EXISTS (SELECT 1 FROM user_profiles WHERE id = auth.uid() AND role = 'admin')
  );
```

### Phase 2: IndexedDB Offline Support
**Goal:** Replace localStorage with IndexedDB for robust offline capability.

#### Step 5: Create IndexedDB Service
Create `src/lib/db/indexeddb.ts`:
- Use `idb` library (lightweight IndexedDB wrapper)
- Schema: `progress`, `practice`, `chapters` (cached content), `pendingWrites` (offline queue)
- CRUD operations: `getProgress()`, `saveProgress()`, `getPractice()`, `savePractice()`
- Pending writes queue: `addPendingWrite()`, `getPendingWrites()`, `clearPendingWrite()`

#### Step 6: Create Sync Engine
Create `src/lib/db/sync.ts`:
- `SyncEngine` class with:
  - `pushLocal()` — upload pending writes to Supabase
  - `pullRemote()` — download latest from Supabase
  - `conflictResolution()` — last-write-wins or merge strategy
  - `onOnline()` — auto-sync when network restores
- Register in `SyncProvider` to replace current localStorage logic

#### Step 7: Cache Chapter Content
Create `src/lib/db/content-cache.ts`:
- Cache chapter `page.tsx` imports in IndexedDB
- Service worker precaches chapter content on first visit
- Offline reading: serve cached content when network unavailable
- Cache invalidation: version-based or manual refresh

### Phase 3: Admin CRUD Panel
**Goal:** Full admin panel to manage chapters, subjects, and content.

#### Step 8: Admin API Routes
Create `src/app/api/` routes:

```
api/
├── chapters/
│   ├── GET /api/chapters          — list all chapters
│   ├── GET /api/chapters/[slug]   — get chapter details
│   ├── POST /api/chapters         — create chapter (admin)
│   ├── PUT /api/chapters/[slug]   — update chapter (admin)
│   └── DELETE /api/chapters/[slug] — delete chapter (admin)
├── subjects/
│   ├── GET /api/subjects          — list all subjects
│   └── PUT /api/subjects/[slug]   — update subject (admin)
├── content/
│   ├── GET /api/content/[slug]    — get chapter JSX content
│   └── PUT /api/content/[slug]    — update chapter JSX (admin)
├── users/
│   ├── GET /api/users             — list users (admin)
│   └── PUT /api/users/[id]/role   — update user role (admin)
└── sync/
    └── POST /api/sync             — bulk sync progress data
```

#### Step 9: Admin Middleware
Create `src/middleware.ts` admin check:
- Verify user is authenticated
- Check `user_profiles.role === 'admin'`
- Return 403 for non-admin users on admin routes

#### Step 10: Admin Pages
Create/update admin pages:

```
/admin
├── /admin/chapters          — list all chapters, filter by subject
├── /admin/chapters/new      — create new chapter form
├── /admin/chapters/[slug]   — edit chapter metadata
├── /admin/subjects          — manage subjects
├── /admin/users             — list users, manage roles
└── /admin/content/[slug]    — edit chapter content (JSX)
```

#### Step 11: Content Editor
For JSX content editing in admin:
- Option A: Form-based editor (structured fields, no code)
- Option B: Monaco editor (code editing in browser)
- Option C: Both — structured form for metadata, code editor for JSX
- Store edited content in Supabase `chapter_content` table
- Override static imports when content exists in DB

### Phase 4: Server-Side Features
**Goal:** Add server-side data fetching, ISR, and dynamic content.

#### Step 12: Chapter Data from Supabase
- Move `chapters.ts` and `subjects.ts` to Supabase tables

#### Step 13: ISR for Chapter Content
- Revalidate chapter content every 24 hours

- Admin edits trigger immediate revalidation

#### Step 14: API for Progress Analytics
Create analytics endpoints:
- `GET /api/analytics/progress` — user progress summary
- `GET /api/analytics/leaderboard` — top learners
- `GET /api/analytics/chapters` — chapter completion stats (admin)

## Technical Decisions

| Decision | Choice | Rationale |
|---|---|---|
| DB schema management | Supabase migrations | Version-controlled, reversible |
| Auth method | Supabase Auth (email/password + anonymous) | Already wired, minimal changes |
| Offline storage | IndexedDB via `idb` library | Better than localStorage for structured data |
| Sync strategy | Last-write-wins with timestamps | Simple, sufficient for single-user per device |
| Content storage | JSX files + Supabase override | Keep static JSX as fallback, DB as source of truth |
| Admin auth | Supabase RLS + middleware check | Secure, layered |
| API style | Next.js Route Handlers | Already in App Router, no extra deps |
| Deploy | Vercel (already configured) | Zero config, edge functions |

---

## Risk Mitigation

| Risk | Mitigation |
|---|---|
| Supabase free tier limits | Monitor usage, add caching layers |
| Offline conflict resolution | Last-write-wins + user notification |
| Admin security | RLS policies + middleware + role check |
| Content migration | Keep static JSX as fallback, gradual migration |
| Build time with 76 chapters | ISR + dynamic imports, no full rebuilds |
